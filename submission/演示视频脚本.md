# 演示视频逐镜头脚本（最终版 · 命令均已实测）

> 目标：openKylin 桌面环境下展示 **≥2 款不同智能体** 的评测，并产出**多维对比雷达图**。
> 时长 3–5 分钟 ｜ 1080p ｜ 旁白清晰、关键数字配字幕。
>
> **录制策略（重要）**：
> - **镜头前只现场跑"内置确定性智能体"**——全量 150 条仅需 **0.59 秒**、0 token、离线可复现，画面干净利落。
> - **真实智能体（KylinBot / Hermes）不现场跑全量**：单回合常达数十秒、个别超过 5 分钟（见"发现缺陷"章节），现场跑会让画面长时间停滞。改为**展示已预置的最终实测结果**（`samples/full-final-150/`），这是真实跑出来的，同样有说服力。
> - 下文命令均已在仓库根目录实测通过，可照抄。

---

## 出场数据（用于字幕/旁白，均为实测）

| 智能体 | 长期保持 | 记忆调用 | 动态更新 | 相近区分 | 边界识别 | 任务复用 | 总体 |
|---|---|---|---|---|---|---|---|
| 参考智能体 reference | 100% | 100% | 100% | 100% | 100% | 100% | **100%** |
| KylinBot（真实·CLI） | 92% | 56% | 44% | 72% | 60% | 76% | **67%** |
| 缺陷智能体 degraded | 100% | 88% | 0% | 60% | 0% | 76% | **54%** |
| Hermes（真实·ACP） | 96% | 56% | 4% | 36% | 12% | 76% | **47%** |

数据集：内置 **150 条**（六维各 25 条，含 20 条跨会话用例）。

---

## Shot 1（0:00–0:25）开场与环境

- **画面**：openKylin 桌面 → 打开终端，`cd` 到项目根目录。
- **旁白**：openKylin 生态已有多款智能体，但"长期记住用户信息"的能力一直难以量化比较；本项目是一套自动化评测基准。
- **字幕**：面向 openKylin 的智能体长期记忆自动化评测 Benchmark。

## Shot 2（0:25–0:50）一键 CLI

- **操作**：
  ```bash
  java -jar target/memory-bench-0.1.0-SNAPSHOT.jar --help
  ```
- **旁白**：封装为 CLI，支持 `--agents-config` 导入智能体、`--parallel` 并行、`--cases` 换数据集、`--repeat` 出稳定性证据；已打包为 `.deb`。

## Shot 3（0:50–1:20）多智能体配置

- **操作**：
  ```bash
  cat examples/agents-final.json
  ```
- **画面**：四款被测对象——`reference`/`degraded`（内置确定性，离线）、`kylinbot`（command 适配器接 openKylin 桌面智能体）、`hermes`（ACP 协议接 Hermes Agent）。
- **旁白**：同一套尺子可接不同形态的智能体，这就是"通用性"。

## Shot 4（1:20–2:05）现场跑：内置两款 × 全量 150 条（秒级）

- **操作**：
  ```bash
  java -jar target/memory-bench-0.1.0-SNAPSHOT.jar run --agents reference,degraded --out out-video-builtin
  ```
- **画面**：**不到 1 秒**跑完 150 条，输出六维对比表：reference **100%** vs degraded **54%**（动态更新 0%、边界识别 0%）。
- **旁白**：全程无需 API Key、离线可复现、重复运行 σ=0——说明"尺子本身"是稳的；两款分数拉开，说明它有分辨力。

## Shot 5（2:05–2:30）内置两款的雷达图

- **操作**：浏览器打开 `out-video-builtin/report.html`
- **画面**：六维雷达对比图。
- **旁白**：不止一个总分，而是六个维度各自的能力剖面。

## Shot 6（2:30–3:20）真实智能体最终实测（重点镜头）

- **操作**：浏览器打开 `samples/full-final-150/report.html`
- **画面**：**四款智能体六维雷达**，其中 KylinBot **67%**、Hermes **47%** 为 openKylin 真实智能体的实测结果。
- **旁白**：
  - 这两款是**真实系统**（KylinBot 走 CLI、Hermes 走 ACP），不是模拟；
  - 它们呈现出**不同的能力剖面**——KylinBot 相近区分 72% 明显强于 Hermes 36%，而 Hermes 长期保持 96% 却在动态更新（4%）与边界识别（12%）上几乎失效。这正是多维指标的价值：能指出每款**具体弱在哪个记忆环节**。

## Shot 7（3:20–3:50）运行证据与逐条产物

- **操作**：
  ```bash
  ls samples/full-final-150/evidence/
  head -n 3 samples/full-final-150/evidence/hermes.jsonl
  ls samples/full-final-150/artifacts/hermes | head
  ```
- **画面**：4 份 JSONL 证据（degraded/hermes/kylinbot/reference）+ 逐条用例的 Markdown 产物。
- **旁白**：对话、记忆、产物统一留证为 JSON Lines 与 Markdown，评审可直接核看——这是"证据闭环"。

## Shot 8（3:50–4:20）可解释归因

- **操作**：
  ```bash
  grep -n "失败归因" -A 12 samples/full-final-150/report.txt | head -20
  ```
- **画面**：每条用例的五分类归因（正确记忆 / 遗漏 / 混淆 / 错误持久化 / 错误复用）与**具体原因**。
- **旁白**：评分不是给个"像不像"的模糊分，而是结构化、可解释地指出失败属于哪一类。

## Shot 9（4:20–4:45）数据集可校验、可扩展

- **操作**：
  ```bash
  java -jar target/memory-bench-0.1.0-SNAPSHOT.jar validate-cases
  java -jar target/memory-bench-0.1.0-SNAPSHOT.jar export-cases --out my-cases
  ```
- **画面**：覆盖度校验（六维各 25 条、跨会话 20 条）；导出后说明产物在 `my-cases/cases.json`。
- **旁白**：数据集外置为 JSON，可增补样本、扩展记忆类型。

## Shot 10（4:45–5:00）收尾点题

- **画面**：回到四款雷达图。
- **旁白**：黑盒、可解释、可复现——服务于 openKylin 社区智能体能力的持续评估与优化。

## 可选镜头（时间充裕才加，需加速播放）

**真实智能体现场小样本跑通**（证明"真的在调真实系统"）：
```bash
java -jar target/memory-bench-0.1.0-SNAPSHOT.jar run \
  --agents-config examples/agents-final.json \
  --cases examples/cases-demo-4.json --parallel 4 --out out-video-demo
```
- 仅 4 条用例；KylinBot 约 30 秒级，Hermes 单回合常数十秒。
- ⚠️ 预计 **1–3 分钟**，务必 **2–4 倍速播放**并保留首尾；若 Hermes 卡顿属正常现象（正是本项目发现的问题之一），不要反复重录。

**openKylin 环境一键验证**：`./scripts/verify-openkylin.sh`（环境采集 + 全量测试 + 评测），可作为开场或结尾的可信度补充。

## 拍摄提示

- 终端字体调大、高对比配色，确保录屏可读。
- 关键数字用字幕强化：**150 条 / 六维各 25 / 100%·67%·54%·47% / 五分类**。
- Shot 4 是"秒级出结果"的强镜头，建议给足停留时间，对比真实智能体的耗时更能体现工具价值。
